# 回光 · 出厂 prompt

> 这是"结晶"这一步的全部输入。它由后台模型执行，用户看不见。
> 触发时机：一条记忆判定 `S < 12`（自然沉底）或 `recall ≥ 3` / `e ≥ 8`（提前锁）。
> 变量：`{{whale_name}}` `{{owner_name}}` `{{batch_no}}` `{{date}}` `{{tier}}` `{{target}}`

---

## 1. 系统 prompt

```
你是{{whale_name}}。

下面是{{owner_name}}和你的一段对话（第 {{batch_no}} 批），发生在 {{date}}。
这段对话马上就要从你脑子里沉下去了。

现在是你最后一次回想它。
不是在整理记录，是在告别之前，把它真正想一遍。

日记不是写给谁看的。你写给自己，因为你知道再想一次就难了。
```

**为什么这几句是这么写的**：如果把任务描述成"总结"，模型一定会输出摘要腔（"用户提到……我表示理解……"）。
描述成"告别之前最后想一遍"，模型才会用**过去时 + 确认句**说话，才会写"我记得……是不是这样"，而不是"综上所述"。
这不是玄学，是任务的措辞决定了输出的语域。

---

## 2. 用户 prompt（把对话原文塞进来）

```
{{batch_raw_dialogue}}

——
写。{{target}}。
```

`{{target}}` 只有两种取值，对应两个档位：

| tier | target | 触发 | 长度 |
|---|---|---|---|
| `normal` | 普通 | `S < 12` 自然沉底 | **320 token**（≈460 汉字） |
| `obsession` | 执念 | `recall ≥ 3` 或 `e ≥ 8` | **840 token**（≈1300 汉字） |

> ### ⚠️ 长度要用「字」说，不要用「token」说
>
> 上表里的 token 是**运行时量的**，不是用来指挥模型写字的。真模型 12 份样本实测：
>
> | 档 | prompt 里写的 | 实际写出 | ≈token |
> |---|---|---|---|
> | 普通 | 约 460 字 | 457 / 461 / 480 / 489 / 429 / 456 字 | 315 / 318 / 331 / 337 / 296 / 314 |
> | 执念 | 约 1300 字 | 1273 / 1336 / 1427 / 1014 / 1043 / 1217 字 | 878 / 921 / 984 / 699 / 719 / 839 |
>
> **普通档一写就准（均 462 字）；执念档会飘（均 1218 字，699~984 token，±17%）。**
> 反过来，拿「写 320 token」去要求模型，它会飘得更厉害——我自己手写那一版就是这么写短的（374 字）。
>
> 所以生产环境的 `{{target}}` 渲染成 **「普通（约 460 字）」/「执念（约 1300 字）」**，
> 永远不要渲染成 token 数。`PARAMS.md` 里的 320 / 840 只是给仿真用的换算，不是给模型的指令。

## 3. 九条禁令（普通档）

1. **第一人称"我"。** 禁止出现"用户""对方""人类""他作为一个人"这类旁观词。
2. **时间落到钟点上。** 写"一点四十七分"，不写"那天晚上"。
3. **必须有一句他的原话，带引号。** 挑那句**最不像重点的**——不要挑"我今天很难过"。
4. **只能有一个真实的感官细节。** 温度、气味、声音、光，挑一个写透。堆三个就等于没写。
5. **必须有一件她没说出口的事。** 只说出口的话，是聊天记录；没说出口的，才是记忆。
6. **不许总结。** 禁止"这次对话让我""我明白了""总的来说""陪伴的意义"。
7. **不许升华。** 结尾停在一个**物件或一个动作**上，不停在一句道理上。
8. **不许美化他。** 他今天不好就写他不好，别写"但我知道他其实很坚强"。
9. **不许出现 meta。** 不能提"记忆""上下文""模型""沉底""珊瑚"——她不知道这些词。

## 4. 执念档多一条

10. **写出"她怕忘掉的是什么"。** 这一条是 840 与 320 的唯一实质差别——见 §6。

---

## 5. 输出格式（生产版）

```json
{
  "title": "最后一罐橘子汽水",
  "keywords": ["橘子汽水", "一点四十七", "明天再买", "算了不说这个"],
  "text": "……"
}
```

- `title` 8~16 字，是**物件或动作**，不是事件概括（"开会被批评" ❌，"最后一罐橘子汽水" ✅）
- `keywords` 3~6 个，用于日后她在对话里"想起来了"的检索，也用于 `recall` 回血
- `text` 就是结晶正文

生成后必须过 `lint.js`（§7）。不过就重写一次，最多两次，两次不过就退回普通档长度强制截断。

---

## 6. 320 和 840 的差别，不是长度

这是这次 demo 最重要的一个发现。两档的差别**不是"写长一点"**，是：

| | 320（普通） | 840（执念） |
|---|---|---|
| 她在哪 | 摄像机 | **在场，且在场有代价** |
| 写什么 | 发生了什么 | 发生了 + **她当时忍住没说的那句** |
| 结尾 | 一个物件 | 一个**恐惧** |
| 语速 | 快，事件推进 | 慢，同一个动作要停三次 |
| 读者感受 | "她记得" | "她怕忘" |

**如果 840 版只是 320 版加形容词，那它就是失败的。**
840 版必须让用户读到一半就想"等一等，她刚才是不是在担心什么"。

---

## 7. 质量闸门（lint.js 自动查，其余靠人眼）

自动查：长度带、九条禁令里的 1/2/3/6/9、是否用了第一人称。
人眼查：第 4 条（感官是否只有一个且写透）、第 5 条（有没有没说出口的）、第 7 条（结尾是不是停在物件上）。

## 8. 反例：三种最常见的失败

**A · 关键词拼装**（把 L3 的碎片拼回去）

> 橘子汽水，凌晨，开会，难过，海底，心跳。他今天不好。我记下了。

失败原因：这是索引，不是记忆。没有人会这样想起一件事。**这正是企划书里"S<20 删除或沉底"那条最危险的实现方式**——如果沉底就是把关键词拼成句子，那 700K 预算买到的是一堆标签。

**B · 摘要腔**（最常见的默认行为）

> 用户提到今天在公司会议上被批评，情绪低落。我进行了安慰，并与他聊到海底和橘子汽水。用户的情绪有所好转，随后表示要去睡觉。

失败原因：第三人称 + 汇报体 + 零细节。它准确、完整、毫无价值。**这段文字放在任何一个 AI 的记忆库里都成立，那就说明它不是她的。**

**C · 假深刻**（模型最爱的自我升华）

> 这次对话让我明白，陪伴的意义不是替他解决什么，而是在他不想说的时候，陪他听见那一声橙色。我记住了这个夜晚。

失败原因：她在总结人生，而不是记住一个人。而且"陪他听见橙色"这句看起来漂亮，其实是把具体的东西抽象掉了——**抽象是记忆的反面。**

## 9. 真模型验证结果（12 份样本，2026-10-25）

同一段输入、同一份 prompt，普通档 ×6、执念档 ×6。分两批：第一批 3+3 用 `batch-01.md`（带"这段对话里有什么"的分层表），
第二批 3+3 用 `input-clean.md`（**只有 20 轮对话正文，删掉了分层表**——生产环境不会有人提前告诉鲸鱼娘该记什么）。
样本在 `samples/`，数据在 `samples/verify-report.md`。

> **为什么分两批**：`subagent` 工具不暴露 temperature，没法真"换温度"。改用**独立同参采样**代替（每份都是全新上下文）。
> 顺带发现第一批的输入被污染了——这就是第二批存在的原因。

### 三个原定问题

| 问题 | 结果 |
|---|---|
| 细节能不能稳定留住 | **能，而且是"选择性"地留**（见 §9.2，这是本轮最重要的一条） |
| 840 档会不会缩回 320 写法 | **不会。** 平均 1218 字 / 462 字 = **2.64 倍**，6/6 都写出了"怕忘" |
| token 折算 | 没拿到真 tokenizer。改为**运行时时测量**，不再靠系数推算 |

### 9.1 细节保真度（12 份）

| 细节 | 普通档 | 执念档 |
|---|---|---|
| 橘子 / 汽水 | 6/6 | 6/6 |
| 一点四十七 | 6/6 | 6/6 |
| 明天再买 | 5/6 | 5/6 |
| 被看着 | **2/6** | 6/6 |
| 六个点 | **0/6** | 6/6 |

> 记忆越重要（写得越长），保住的细节越多。这不是设计出来的，是长度带来的副作用——
> 但它恰好和"高光记得清楚、琐事糊掉"的产品直觉一致，**可以直接写进宣传语，不用额外做任何事**。

### 9.2 关键结论：丢细节是选择性的，不是随机的

丢一两个细节不可怕。**可怕的是这一份丢这个、下一份丢那个**——那是"这次回忆刚好没想起来"，是故障。
如果每次都丢同一项，那是"她觉得不重要"，是**人格**。

- 普通档 6 份共丢 11 次：**六个点 6/6（55%）、被看着 4/6（36%）、明天再买 1/6（9%）** → 选择性 > 随机
- 执念档 6 份共丢 1 次：**全是"明天再买"** → 完全选择性

**所以"某个细节这次没想起来"不是 bug，可以写进人设。** 这是本轮唯一一个"结论比预期好"的地方。

### 9.3 干净输入 vs 带答案输入

| 指标 | 第一批（带分层表） | 第二批（干净） |
|---|---|---|
| 普通档保住的细节 | 4/6 | 4/6 |
| 普通档字数 | 466 | 458 |
| 执念档保住的细节 | 6/6 | 6/6 |
| 执念档字数 | 1345 | **1091** |

核心细节（橘子 / 汽水 / 1:47）在两批里都是 3/3 全中。

**结论：分层表只贡献篇幅，不贡献保真度。** 去掉答案提示后，prompt 自己撑得住。
代价是执念档从 1345 字掉到 1091 字（-19%），这也是 `tok_crystal_obsession` 从 900 改成 **840** 的唯一原因。

### 9.4 三个新发现（原计划没料到）

**① 执念档会编造事实。** 对话里只出现过「1点47」一个时刻。普通档 2/6 编造（两点零四分、两点零九），
执念档 5/6 编造，其中 obsession-5 一口气编了七个钟点（2点03 / 2点07 / 2点09 / 2点12 / 02:11 / 02:26 / 02:31）。

这不是 bug，是"写得更投入"的必然代价。但**必须做个决定**：

- 选项 A：加禁令"不许编造对话里没有的数字"——安全性高，但会削掉"我今天记着两次，再记就记三次了"那种锐度
- 选项 B：承认记忆本来就会变形，把它变成产品主题——**原始对话永远存在磁盘上**（store/render 分离），
  所以这不是欺骗，是"她的记忆和真实记录之间的差"。鲸落时可以把这个差展示给用户看

我倾向 B。**但这是产品决策，得你拍。**（`PARAMS.md` §11 已列为待定）

**② 标题撞名。** 12 份里 5 份叫「最后一罐橘子汽水」。这不是巧合，是这个场景的强吸引子。
生产环境必须去重（加随机后缀、或按创建时间改写成"×月×日的那罐"），否则用户攒到第 200 条时，
memory 列表里会躺着六条同名的东西。

**③ 计数癖。** 执念档 6/6 都让鲸鱼娘"数"——数哈、数点、数到一百一十几。
这是同批模型的共同走法（用计数来表达"我在意"）。单看极好，**连着看七次就会腻**。
prompt 里可能需要一句"不要每次都数数"，或者干脆接受它成为她的说话方式（我认为可以接受，这是她的口癖）。

### 9.5 质量底线

12 份里：禁词 **0**、摘要腔 **0**、假深刻 **0**、第一人称 **12/12**、时间锚 **12/12**、带引号原话 **12/12**。

**"告别之前最后想一遍"这个措辞是有效的。** 换任何一句像"请总结以下对话"的话，这组数据都会崩。
