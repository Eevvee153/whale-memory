## 4. 长度与 token 折算

**这个系数仍然是估的。** 本轮没有拿到 DeepSeek 真正的 tokenizer，所以：

- 结论一：**不要在 prompt 里写 token 数**，写汉字数（460 / 1300）。模型不认 token。
- 结论二：寿命公式里那条"每条结晶多少 token"，**运行时用实测均值替换**，不要写死 320/840。
  每次结晶后记一次 `usage.input - 上一次`，滚动平均，寿命自然准。

## 6. 稳定性：丢细节是随机的，还是有选择的

这一节才是本轮真正要回答的问题。丢一两个细节不可怕——**可怕的是一份丢这个、下一份丢那个**。
前者是"她觉得不重要的就糊掉"，后者是"这次回忆刚好没想起来"。前者是人格，后者是故障。

### normal（6 份，共丢 11 次）

每份丢掉几个：1 / 3 / 2 / 2 / 2 / 1

| 细节 | 丢了几份 | 占全部丢弃 |
|---|---|---|
| 六个点 | 6/6 | 55% |
| 被看着 | 4/6 | 36% |
| 明天再买 | 1/6 | 9% |

> ✅ **选择性 > 随机**：最常丢的那一项占了多数。有规律，可以接受，甚至可以做成人设。

### obsession（6 份，共丢 1 次）

每份丢掉几个：0 / 0 / 1 / 0 / 0 / 0

| 细节 | 丢了几份 | 占全部丢弃 |
|---|---|---|
| 明天再买 | 1/6 | 100% |

> ✅ **完全选择性**：每次丢的都是同一项。这是"她认为不重要"，可以写进人设，不是 bug。

## 7. 两批对比：旧输入（带分层表）vs 干净输入

第一批（-1..3）读的 `batch-01.md` 末尾有一张"这段对话里有什么"的分层表，直接点明了哪句是重点。
第二批（-4..6）读的 `input-clean.md` **把那张表删了**——生产环境里不会有人提前告诉鲸鱼娘该记什么。
如果第二批明显变差，说明 prompt 撑不住，之前的成绩有一半是那张表给的。
